# Predictive Analytics for Sales Forecasting: A Reproducible ML Pipeline with DVC

## Problem and dataset

This DS-4491 project predicts daily sales from historical sales. If no sales file is provided, `src/make_sample_data.py` deterministically creates 1,095 daily records (three years) with a gradual trend, yearly seasonality, weekend effects, and seeded noise. The raw CSV has two columns: `date` and `sales`. Preparation sums duplicate dates into daily totals and sorts chronologically.

This is a one-step-ahead forecast: the previous day's actual sales are assumed to be known when forecasting the next day. Rolling means use `shift(1)`, so a row never includes its own target value.

## ML model

A `RandomForestRegressor` predicts `sales` using month, day of week, ISO week of year, configured sales lags, and a rolling mean of past sales. The last 20% of feature-ready dates form the test set; earlier dates form the training set. The split is chronological, never random. Evaluation reports MAE, RMSE, and MAPE.

## DVC pipeline

```text
sales.csv -> prepare -> train -> evaluate -> metrics.json
```

- `dvc.yaml` declares stage commands, dependencies, parameter groups, outputs, and the metric file. The dependencies form `prepare -> train -> evaluate`.
- `params.yaml` controls `lag_days`, `rolling_window`, and `test_size` for preparation, plus `n_estimators`, `max_depth`, and `seed` for training.
- `prepare` aggregates daily totals, adds month/day-of-week/ISO-week and past-only lag/rolling features, drops warm-up rows, then assigns the last 20% of dates to test.
- `train` fits a random forest on `train.csv` and saves `models/model.pkl` with joblib.
- `evaluate` scores the held-out `test.csv` and writes MAE, RMSE, and MAPE to root `metrics.json`. DVC treats this metric as uncached (`cache: false`).

## How to run the project

Run from the project root in PowerShell. Skip `git init` if Git is already initialized. Generate sample data only when `data/raw/sales.csv` has not been supplied. Run `dvc init` only once per repository.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt

git init
dvc init
python src/make_sample_data.py
dvc add data/raw/sales.csv
dvc remote add -d myremote ../dvc-storage

git add .
git commit -m "Add reproducible sales forecasting pipeline"

dvc repro
dvc dag
dvc status
dvc push

git add dvc.lock metrics.json
git commit -m "Record reproducible forecasting results"
```

For an existing GitHub checkout, configure access to its shared DVC remote, then run:

```powershell
git clone https://github.com/USERNAME/sales-forecasting-dvc-pipeline.git
cd sales-forecasting-dvc-pipeline
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
dvc pull
dvc repro
```

The example `../dvc-storage` is a local same-machine remote and is not uploaded by GitHub. For another machine, configure a shared DVC remote instead. Do not commit cloud credentials.

## Viva demos

1. Change `train.n_estimators` from `200` to `250` in `params.yaml`, then run `dvc repro`. `prepare` is skipped because its parameters and dependencies are unchanged; `train` and `evaluate` rerun.
2. Restore `n_estimators` to `200`, change one value in `prepare.lag_days`, and run `dvc repro`. `prepare` reruns, changes its outputs, and causes `train` and `evaluate` to rerun.
3. Edit a value in `data/raw/sales.csv` and run `dvc status`. DVC reports the raw-data dependency changed and the pipeline needs reproduction. Restore the input with `dvc checkout` or regenerate it, then run `dvc repro`.
4. After a successful `dvc push`, remove `data/processed/` and `models/`. Run `dvc pull` to restore outputs from the remote, or `dvc repro` to recreate them from the raw data and code.
